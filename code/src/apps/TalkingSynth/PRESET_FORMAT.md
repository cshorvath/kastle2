# Talking Synth presets v1

Byte-oriented little-endian format, magic `k2ts`. Stored at `0x10080000` in
RP2040 XIP flash. The parser validates counts and exact size before dereferencing
records, then verifies CRC32 and trailer. It allocates no bank/phrase data.

| Header offset | Size | Field |
|---|---|---|
| 0 | 4 | ASCII `k2ts` |
| 4 | 4 | Total byte length, including header and trailer |
| 8 | 4 | IEEE CRC32 of bytes `[32,total_size)` |
| 12 | 2 | Version = 1 |
| 14 | 1 | Bank count, 1–32 |
| 15 | 1 | Phrase slots per bank, 1–32 |
| 16 | 1 | Scale count, 1–32 |
| 17 | 1 | Rhythm count, 1–64 |
| 18 | 1 | Sequencer length, 2–64 (framework bounds) |
| 19 | 13 | Reserved, writers emit zero |

After the header: `scale_count` uint32 masks (nonzero, low 12 bits) followed by
`rhythm_count` uint32 masks. Their meaning is the existing framework quantizer
and TriggerGenerator bit ordering. Sequencer lengths above 32 retain the
framework's interpretation of the 32-bit pattern, not a new 64-bit rhythm format.

Each bank has a 16-byte header: eight ASCII name bytes (zero padded, or full eight
characters), RGB at bytes 8–10, five reserved zero bytes. Then its fixed number
of **80-byte** phrase records:

| Phrase offset | Size | Field |
|---|---|---|
| 0 | 64 | Zero-terminated text, maximum 63 ASCII characters |
| 64 | 1 | Speed, 1–255 (higher is slower) |
| 65 | 1 | Mouth, 1–255 |
| 66 | 1 | Throat, 1–255 |
| 67 | 1 | Sing mode, 0 or 1 |
| 68 | 12 | Reserved, writers emit zero |

The trailer is ASCII `ahoj`. Total size must be exactly:

`32 + 4*(scale_count + rhythm_count) + bank_count*(16 + 80*slots_per_bank) + 4`.

The editor converts text to uppercase on binary export; JSON retains typed text.
Its supported text alphabet is English letters, digits, spaces and `.,?!'-`.
Internal SAM phonemes are generated on-device, not stored in the preset image.
Pitch is deliberately absent: the hardware controls it independently of speed.

JSON work files use `format: "kastle2-talking-synth"`, `version: 1`,
`sequencerLength`, arrays `scales` and `rhythms`, and `banks`. Each bank has
`name`, six-digit `color` (`#rrggbb`), and a `phrases` array. Each phrase has
`text`, numeric `speed`, `mouth`, `throat`, and boolean `sing`. JSON import
validates the complete project before replacing editor state.

UF2: 512-byte blocks, 256-byte payload, flags `0x2000`, family ID `0xe48bff56`.
The editor validates the uploaded firmware-only UF2 before merging and rejects
bad magic, wrong family, non-256-byte payloads, overlapping/out-of-range
addresses, duplicate blocks, invalid sequence counts and missing boot/program
identity. Firmware data must remain below `0x10080000`; preset blocks start
there. Merged block numbers/counts are regenerated by the shared UF2 writer.
